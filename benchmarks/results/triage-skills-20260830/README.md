## Corpora (`cases.json`)

- **blocker_cases (23)** — every live stale-blocker finding from `check-closability.py --json`: an open item mentioning a since-resolved item near blocker-ish words. Record = item id/status/title, target id/now-status, and the selector's context excerpt. Labels adjudicated by hand: 6 `lifted`, 12 `not-a-blocker`, 1 `still-blocking`, 4 `unclear`.
- **staleness_cases (12)** — items flagged by the age-only `check-staleness.py`: 5 open/stale bugs + 7 completed feats. Record = frontmatter facts + the last 1300 chars of body. Labels: 5 `follow-up-needed`, 7 `fine`.

Scoring: exact verdict match; `unclear` on a labeled case is a tracked safe-miss; any other mismatch is a wrong verdict (the failure that matters in a report a human trusts).

## Reading

- **The loop structure worked as designed.** Every loop-1 failure was legible from the model's own `reason` string, and each fix was one reading-rule edit. The trajectory (16→22→23) is skill-text improvement, not noise: repeats-3 unanimity on loop 3 says the final behaviour is stable at temperature 0.
- **Two "model failures" were label failures.** TASK-253 (the model applied the explicit-denial rule the skill states) and FEAT-029 (the model found real unchecked boxes the labeler missed). On a corpus this small, the model auditing the labels is a feature — but it also means the final 23/23 + 12/12 includes 2 cases where the label moved toward the model. The other 33 labels never moved.
- **Contamination note:** the blocker skill quotes TASK-1193 (one corpus case) as its worked input example, per house style. The staleness skill's example uses BUG-138's frontmatter but rules were genericized away from corpus phrasing after drafting.
- **Known limits:** one model, one run night, 35 cases total; the `unclear` path of staleness.triage was never exercised (no case needed it); the blocker lane's `unclear` class exists mostly because `check-closability`'s excerpts truncate — widening the selector's context window would shrink it at the source and is the highest-leverage next change.

## Post-review corrections (2026-08-31) — the honest numbers are 22/23 and 12/12-on-a-corrected-corpus

An independent review of commits `a0c45d2e`/`5bd408d` sustained four findings; all verified against the sources and all are now fixed:

1. **TASK-253→BUG-217 relabel reverted.** `BUG-217` never appears in the supplied excerpt, and the skill's top rule mandates `unclear` when the target id is invisible — the loop-1 move to `not-a-blocker` contradicted the pinned contract and made the 23/23 circular. Label restored to `unclear`; the model still answers `not-a-blocker` via the denial phrasing, so **blocker is 22/23**, and the residual miss names a real skill gap: the truncation rule and the explicit-denial rule need an explicit priority when both fire.
2. **BUG-052 was a confident false negative.** The full entry marks Fix and Verification "Under investigation" just above the 1300-char window; the recorded `fine` (matched by the model) was exactly the wrong-`fine` failure the skill says matters most. Label corrected to `unclear`, and the skill gained a visible-evidence rule (an open item whose tail shows neither fix nor verification state is `unclear`, not `fine`). On the rerun the model answers `unclear` — **staleness 12/12 on the corrected corpus**.
3. **`check-staleness.py` rewritten to a recursive scan.** The old hand-enumerated `SCAN_DIRS` + non-recursive glob skipped project-nested tasks (424 files) and all of `improvements/` (184 files). Now: six roots, `rglob`, `index.md` excluded, deduped — 357 → 1,397 files scanned, 78 previously invisible stale hits. This corpus therefore predates the lane's real input population; a rerun on the wider selector output is owed before production wiring.
4. **Vote aggregation fixed and tested.** `run_triage` stored `raws[-1]` (a split vote could pair the majority verdict with the dissenting rationale) and accepted replies missing the required `reason`. Now: `validate_triage_vote` requires a non-empty reason, `pick_winning_raw` stores a rationale from the winning vote, all raw replies are retained per case, and `_scripts/test-proposer-shadow.py` (16 tests) pins the reproduced failures.

Post-review measured run: `{blocker,staleness}-postreview.json` (run dir `…T131146Z`). Registry re-pinned against the corrected staleness skill with the honest numbers.
