# IMPR-1032 Phase A — v0.4.4 → v0.4.7 compat pre-check (2026-07-04)

Findings from the no-cluster-change pre-check defined in IMPR-1032. Verdict: **direct
bump is clear**; no migration steps required, one init container drops out.

## Checklist results

| #   | Check                                                                                    | Result                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| --- | ---------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | http `ov-vectordb` vs v0.4.7 VikingDB schema additions                                   | **Compatible in lockstep.** The v0.4.7 note requiring manual `content` (text) + `search_tags` (list\<string\>) field additions applies to the managed Volcengine VikingDB cloud backend, where the operator owns the collection schema. Our vectordb is the bundled self-hosted store (`openviking.storage.vectordb.service.server_fastapi`, same image as the server) and is bumped in the same rollout; v0.4.6 additionally shipped "legacy collection schema compatibility" fixes for exactly this case. Post-bump verification: `ov status` vikingdb health + a search read-path smoke. |
| 2   | `role-value-patch` init container obsolescence                                           | **Obsolete — removed.** The init container rewrites `.role.value` → `.role` and enum-style `Role` iteration; v0.4.5's release notes name this exact fix ("deploy this release for the role serialization fix if you run authenticated or trusted-mode multi-tenant deployments" — our shape). Dropped the init container, the `/ov-patch` volume + mounts, and the `PYTHONPATH=/ov-patch` override.                                                                                                                                                                                         |
| 3   | `config-rewrite` init container                                                          | **Still required** — injects `root_api_key` and Garage S3 creds into `ov.conf`; unrelated to any upstream fix.                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| 4   | `temp-cleanup` init container                                                            | **Kept.** v0.4.7 improves temp-write/lock paths (temp-file publish, QueueFS lock-reuse fixes), but the stale-pid/LOCK/`.path.ovlock` cleanup is harmless belt-and-braces on Recreate restarts. Candidate for removal after v0.4.7 has soaked.                                                                                                                                                                                                                                                                                                                                               |
| 5   | v0.4.6 breaking change (`agent_id`/`agent_uri` no longer a peer selector on search/find) | **No blast radius.** No consumer passes either field in search/find request bodies: `viking/`, `compendium/_scripts/`, `~/code/omnipendium`, and hermes all clean (hermes `agent_id` hits are mem0-only; `OPENVIKING_AGENT` is an identity header, not a body field). Replacement selectors if ever needed: `actor_peer_id`, `X-OpenViking-Actor-Peer`, or explicit `target_uri`.                                                                                                                                                                                                           |
| 6   | Legacy 0.3.x agent/session data (would force a 0.4.5 migration stop)                     | **None.** `viking://agent/` contains only the 0.4.x-style `agent/default` scope (created 2026-07-05); `viking://session/` is empty. Release notes: existing 0.4.x deployments upgrade directly.                                                                                                                                                                                                                                                                                                                                                                                             |
| 7   | CLI/SDK skew                                                                             | The 0.3.14 CLI seen at check time was a **stale root-owned binary at `/usr/local/bin/ov`** shadowing the uv-managed CLI (then 0.4.6). The uv tool was upgraded to **0.4.7** during the 2026-07-04 doc sweep, but the shadow still wins PATH — remove with `sudo rm /usr/local/bin/ov` (and check the `~/.bun/bin/ov` shim between them). v0.4.7 CLI still has the first-run language gate, so the exporter's `ov language en` workaround stays. No Python SDK consumers yet (compendium-sync uses raw REST).                                                                                |
| 8   | Queue state                                                                              | Drained at check time: 0 pending, 3 in-progress semantic, 0 errors. Note: 485 semantic requeues historically; v0.4.7 fixes embedding-auth infinite requeue.                                                                                                                                                                                                                                                                                                                                                                                                                                 |
